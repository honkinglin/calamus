## 2026-11-13 · 完整场景与保留堆内存

运行 `pnpm bench`，输出结构化 JSON。环境：Apple M3 Pro / arm64，macOS（Darwin 27.2.0），Node v24.14.0。每组预热 5 次、测量 30 次；中位数取中间两个值均值，P95 使用 nearest-rank。每次计时涵盖该场景全部笔画。

| 场景 | 操作 | 中位数 ms | P95 ms | 输出保留堆 MiB |
| --- | --- | --- | --- | --- |
| 1 笔 × 1,000 点 | 采样处理 | 0.102 | 0.240 | 0.157 |
| 1 笔 × 1,000 点 | 几何生成 | 0.445 | 0.992 | 1.585 |
| 1 笔 × 10,000 点 | 采样处理 | 0.761 | 0.866 | 1.437 |
| 1 笔 × 10,000 点 | 几何生成 | 2.568 | 8.133 | 15.295 |
| 100 笔 × 100 点 | 采样处理 | 0.785 | 1.200 | 1.460 |
| 100 笔 × 100 点 | 几何生成 | 1.890 | 2.984 | 14.362 |

所有坐标位于逻辑画布范围内，输入为确定性正弦轨迹。与上方旧基准的坐标分布不同，不能直接把两次差值当作优化收益。

内存使用 `node --expose-gc`：预热之后强制 GC，记录 heapUsed，生成并保留完整输出，再 GC 后记录差值。每项内存只采样一次。该指标是输出对象的近似保留成本，不是峰值、总分配量、内存泄漏证明或 Canvas/GPU 内存；GC 与运行环境会带来波动。负差值按 0 报告，不代表零分配。未启用 GC 时返回 null。

1 万点完整几何输出保留约 15 MiB，说明后续活动笔画增量处理与分配控制值得优先测量。浏览器绘制、合成和输入响应仍需另外测量，本轮没有新增性能优化或设备通用帧率承诺。

| --- | ---: | ---: |
| 原始逐次几何检测 | 154.957 | 159.100 |
| 每轮创建新手势缓存 | 0.613 | 0.766 |
| 复用已预热手势缓存 | 0.093 | 0.109 |

[原始结果](benchmarks/eraser-2026-11-13.json)。这是 Node 命中查询微基准，不包含 Canvas 重绘或真实 pointer 事件，不能等同于用户可感知延迟或一般画作加速比。

实现采用处理后笔尖与半径的保守笔画边界，快速排除远处查询；进入候选后缓存多边形及其边界，再使用原有精确扫掠算法。缓存只用于引擎内部已提交、不会再修改的笔画，同一手势内复用；普通函数入口仍无缓存，避免调用方修改输入后得到旧结果。

每个手势最多缓存 32 笔、100,000 个几何顶点，按最近使用顺序淘汰；单笔超过顶点预算仍正常检测但不留存几何。预算只限制缓存，不限制单次几何生成的临时峰值，也不是精确字节上限。手势结束、取消、工具切换、历史操作和销毁会经结束/取消路径清理。原始边界以 WeakMap 保存，不保留额外强引用。

橡皮未命中时不再将已完成画布标记为脏，避免每次移动重画全部笔迹。自动化覆盖 640 组与原算法的对照、边界相切、空笔画、缓存预算与清理，并验证未命中不重建画布、不创建历史。浏览器实机擦除交互本轮尚未完成，不以算法测试替代它。

## 不透明活动笔画栅格前缀缓存（2026-11-13）

完整的 64 段批次逐批加入离屏画布，后续帧复合前缀图像并重绘不足 64 段的尾部。固定测试覆盖 1、63、64、65、127、128、重复 128、193、300 段前缀：缓存上下文累计提交段数始终为 `floor(count / 64) * 64`，而不是各帧前缀之和；当前画布只提交尾段和图像合成。此计数不是耗时基准。

缓存只针对默认 source-over、不透明十六进制颜色，无滤镜或阴影的活动笔画。预算 4,000,000 物理像素，对应单个 RGBA 缓冲区约 16 MB，不包含浏览器额外副本和其他画布；它不是整页内存上限。几何缓存超限、像素超预算或上下文不可用时回退；DPR 变化会重建完整前缀。手势结束或取消释放画布。

浏览器像素、内存和帧耗时尚未实测。离屏抗锯齿及合成舍入可能造成像素差异，单元测试仅验证有序批次及生命周期。透明长笔画仍使用整笔一次填充，其栅格瓶颈尚未解决。

## 活动透明笔画路径缓存（2026-11-15）

活动手势在几何缓存预算内使用 Path2D 追加新多边形，每帧仍以 nonzero 规则一次填充整笔，避免通过分批 alpha 合成引入交叉加深。路径使用逻辑坐标，随 Canvas 当前变换绘制；提交、取消、销毁及几何缓存溢出时释放引用。不透明可分批路径保持原实现。

缓存上限为 100,000 顶点，浏览器不支持 Path2D 时保留原渲染回退。该优化仅减少重复的 JavaScript 路径构建/提交，不减少 Canvas 对整条透明路径的栅格化工作；额外 native Path2D 内存由浏览器管理。命令级回归通过，浏览器像素对照、实际帧时间与内存测量仍待完成。

### 重复采样补充

诊断报告 schemaVersion 2 将新增几何首次提交独立记录，并在每个规模先预热 2 对、再测量 10 对不变几何重绘，交替缓存/参考渲染顺序，保留原始样本、中位数与 nearest-rank P95。报告见 benchmarks/path-cache-repeated-2026-11-15.json。

实测 10 组像素仍完全一致。2000 点时首次追加约 78.5/82.1ms（1×/2×），缓存不变路径提交中位数均为计时精度下的 0ms，参考路径约 105.9/104.2ms。零值不表示 GPU 或绘制工作为零；不变路径重复提交也不代表真实增长笔画的输入延迟。下一步优先分析新增路径成本，而非将暖缓存重绘当成交互性能结论。

### 小批量增长场景

报告 schemaVersion 3 在 2000 点后依次追加 1、16、32 点，记录 addedPoints 和场景类型；几何预计算不计入时间。结果见 benchmarks/path-cache-growth-2026-11-15.json。16 组（两个 backing-store 尺度）均无像素差异。

本机此次首次追加提交时间：1× 为 0.2、2.0、3.7ms；2× 为 0.2、2.1、4.0ms。此前约 80ms 的结果对应从 1000 点一次增长到 2000 点，不应解释为追加单点或典型逐帧输入的耗时。小批量增长每种仅一次测量，仍不能推导稳定输入延迟或 FPS；完整引擎采样、几何构建、合成、GPU 完成与 native 内存待测。

### 引擎公开 API 渲染回归

使用同一个 `pnpm bench:path:browser` 服务打开 `/engine-browser.html`。固定两笔各 500 点透明交叉曲线，检查清空撤销、重做撤销、JSON 往返、PNG 往返、回放暂停恢复及取消。报告见 benchmarks/engine-replay-2026-11-15.json。

首次默认 Canvas 上下文读回出现最大 1/255 通道差异；将诊断主画布和 PNG 比较画布在构造 SDK 前设置 willReadFrequently 后，六项均为零差异，JSON 不变且暂停稳定。后者仅是固定读回上下文条件下通过，支持后端差异假设但不证明根因；不将默认 GPU/CPU 后端一致性标为通过。正式 SDK 未修改上下文配置。原始报告在 readbackContext 元数据加入前下载，本段记录实际运行条件。

这些检查通过 SDK 公开 API，不覆盖真实 pointer 事件、活动笔画缓存、设备 DPR 切换或内存。PNG 只验证文档往返前后的导出一致性，不将其与缩放显示画布逐像素比较。

### 默认上下文读回差异隔离

engine-browser.html 现在可选择默认或 willReadFrequently 上下文，每次运行替换为全新 Canvas，避免复用已创建上下文。报告 schemaVersion 2 分开记录 RGB 与 Alpha 差异，并增加不重绘连续读取的对照。

本机默认上下文中，不执行任何 SDK 重绘的第二次 getImageData 即出现 125371 个 RGB 像素变化，最大通道差为 1，Alpha 零变化；历史/JSON/回放项呈现相同数量级差异。固定读回上下文 7 项均为零差异。详见 engine-default-2026-11-15.json 和 engine-readback-2026-11-15.json。

因此该误差可以在没有历史或回放操作的情况下复现，不能单凭它认定引擎功能错误。具体浏览器内部机制仍未证明，也不宣称所有浏览器同样表现。默认模式仍保留严格失败标记，不通过增加容差掩盖差异；正式 SDK 上下文选项不变。

### 诊断任务控制

两个诊断页面支持 Cancel checks；页面隐藏或离开时自动取消。每次等待 rAF 最多 5 秒，停止时释放调度与事件监听，报告只在所有检查完成后可下载。同步 Canvas 操作无法在执行中被中断，取消在浏览器下一次处理事件后生效。取消后的任务会通过 finally 释放临时路径/画布或 SDK 实例，可重新运行。
