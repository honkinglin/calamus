# 发布前检查

本清单描述尚待完成的发布流程，不代表已发布或可直接移除 `private: true`。实现进度以[开发计划](DEVELOPMENT_PLAN.md)为准。

## 身份与内容

- [ ] 确认 npm 包名/scope 和发布身份（GitHub 仓库已确认）。
- [ ] 确认作者署名、许可证及所需第三方声明，再将许可证纳入仓库与包。
- [ ] 确认首版交付范围：当前 ESM + UMD；Worker 填充不能列为已支持，UMD 桌面浏览器绘制、生命周期和 JSON 下载已验收。
- [ ] 更新版本、CHANGELOG、包元数据、README 链接、截图与演示素材。
- [ ] 检查网站和文档中的功能描述与最终版本一致。

## 产物与自动化

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm example:build
pnpm size
```

`example:build` 包含实际 tarball 的外部离线安装、依赖/exports 检查、严格 TS/JS 消费和示例构建。包检查会拒绝白名单以外的归档路径；若有意添加新产物，需要同步审核白名单，而不是绕过检查。

- [ ] 上述命令在最终待发布提交通过，远端 CI 也通过。
- [ ] 检查最终 tarball 清单：只包含预期代码、声明、元数据、说明与许可证。
- [ ] 记录最终包体积和性能条件，确认无私密文件、临时资产或工作区路径引用。

## 浏览器与设备

- [ ] 绘制→擦除→撤销重做→导出→重新导入流程。
- [ ] 刷新恢复、作品切换、存储错误和可恢复删除。
- [ ] 透明/不透明交叉笔画、DPR 变化、取消输入、回放与导出一致性。
- [ ] 栅格缓存的像素对照、真实帧耗时与内存检查。
- [ ] 原生示例绘制、下载、销毁/重建、响应布局与键盘焦点。
- [ ] 目标浏览器与真实触控设备检查，记录未覆盖设备及限制。

## 发布后验证

- [ ] 仅在发布目标和身份明确后启用发布配置并发布包。
- [ ] 从 registry 安装最终版本，重复消费者检查。
- [ ] 部署网站并检查生产地址，而非仅检查本地构建。
- [ ] 创建 release，填写实际网站/npm/源码链接、版本和限制。
- [ ] 更新仓库 About、topics 和最终展示素材。

没有有效工具结果或人工验收记录时保留未勾选状态。单元测试和构建不能证明浏览器像素、触控体验或线上发布成功。

## 本地发布预检

执行 `pnpm release:check`；机器可读报告使用 `node scripts/release-readiness.mjs --json`。
检查包名/版本的基本格式、发布开关、说明、作者、许可证文件与元数据、仓库、scoped 包的 public access 及构建入口是否存在。任一缺项退出码为 1；这在发布准备阶段是预期结果。命令只读，不修改配置或执行发布。

此命令不核实 npm 名称占用、账号权限、完整 SPDX/semver 语法、许可证内容合法性、产物新旧或浏览器质量。需结合实际 tarball 检查和人工验收；不要为了让预检变绿提前开放发布。
