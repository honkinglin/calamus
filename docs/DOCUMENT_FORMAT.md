# 文档格式 v1

`exportJSON()` 输出如下结构，`parseDocument()` 校验并规范化它。原始采样是文档事实来源，平滑点、几何和栅格缓存均不持久化。

```json
{
  "schemaVersion": 1,
  "width": 1000,
  "height": 700,
  "strokes": [
    {
      "brush": {
        "color": "#253631",
        "size": 6,
        "smoothing": 0.55,
        "stabilizer": 8,
        "velocityWidth": true
      },
      "points": [
        { "x": 20, "y": 30, "time": 0, "pressure": null },
        { "x": 40, "y": 45, "time": 8, "pressure": null }
      ]
    }
  ]
}
```

## 坐标与时间

`x`、`y` 使用逻辑画布坐标，不是 CSS 像素或设备像素，允许负数和超出画布范围。`time` 是笔画内部相对毫秒，非日历时间；每笔独立且单调不减。`pressure` 为 0–1 的笔压力；`null` 表示没有硬件压力，可启用速度宽度。零压力与 null 不相同。

## 导入限制

| 内容 | 校验边界 |
| --- | --- |
| JSON 输入 | 字符串长度不超过 20,000,000 个 JavaScript UTF-16 码元；这不是严格 UTF-8 字节数 |
| schemaVersion | 仅接受数字 1，没有隐式版本迁移 |
| width / height | 有限数，1–32,768；引擎导入还要求与实例逻辑尺寸一致 |
| strokes | 最多 10,000 笔，允许空文档 |
| points | 每笔至少 1 点，全部笔画累计最多 250,000 点 |
| x / y | 有限数，−1,000,000 至 1,000,000 |
| time | 有限数，0–86,400,000，笔内单调不减 |
| pressure | null 或 0–1 有限数 |
| color | 以 # 开头的 3/4/6/8 位十六进制颜色 |
| size | 有限数，0.01–4,096 |
| smoothing | 可省略，规范化默认 0，范围 0–1 |
| stabilizer | 可省略，规范化默认 0，范围 0–4,096 |
| velocityWidth | 可省略；提供时必须为 boolean |

注意：文件中省略 smoothing 的默认值是 0，而新建引擎默认笔刷为 0.55；文档规范化不会套用 UI 或实例当前笔刷。JSON 不支持 NaN 或 Infinity。

校验返回新的对象，未知字段不保留。SDK 不承诺保留外部扩展字段，因此作品名称、缩略图、纸色和其他元数据应放在应用自己的存储记录中。

## 实时输入容量

实时绘制也遵守 10,000 笔与 250,000 点限制，通过 `onInputLimit` 报告容量不足。超限新增手势被取消，旧文档不变。擦除仍可用；橡皮只保留最新扫掠端点，不消耗持久文档点数。撤销/重做、导入和清空后按当前文档重算容量。字符串长度仍是独立导入限制，点数检查不保证任意精度数据的 JSON 都小于 20,000,000 码元。

## 历史与迁移

- `loadJSON(json)` 默认创建一条可撤销替换记录。
- `loadJSON(json, { resetHistory: true })` 用于打开独立作品，清空 undo/redo。
- 校验失败不会覆盖现有文档；有效但尺寸不同的文件应创建匹配逻辑尺寸的新引擎后再导入。
- 历史、当前手势、回放状态、缩放、主题和存储标识不属于文档格式。

未来改变格式时应新增明确版本和迁移策略；当前不要手动修改 schemaVersion 来绕过校验。
