## 1. 产品目标

Calamus 是一个打开即可书写、绘画和保存作品的在线画板，同时提供可独立安装的 TypeScript 绘图引擎。

交付物：

1. 在线工具网站：以画板为入口，包含作品管理、导入导出、设置和开发者文档。
2. npm 包：框架无关的绘图引擎，网站直接消费该包。
3. GitHub 开源项目：源码、测试、示例、架构说明、贡献指南、截图和发布记录。

项目代码、视觉和文案独立设计。文档围绕自身能力组织，不加入其他画板项目的对比或参考叙事。第三方依赖或复用代码所要求的许可证与声明保留。

## 3. UI 与交互方案

设计方向：安静、精细的数字书写工作台。默认暖白纸面、石墨色文字、克制的青绿色强调色；深色模式只改变界面，不自动改变作品颜色。图标采用统一开源图标库，保留许可。

- 桌面：顶部品牌、作品名和保存状态；左侧紧凑工具栏；居中纸面；可折叠属性面板；底部缩放与历史操作。
- 平板：扩大触控目标，属性面板按需展开，保留大面积画布。
- 手机：底部工具栏与抽屉式属性面板，适配安全区域，避免操作被浏览器工具栏遮挡。
- 新用户直接进入可画状态；空白状态提示简短，可关闭。
- 所有按钮有真实行为；未完成能力不显示成可点击功能。
- 清空可撤销；导入替换与删除作品有明确反馈；自动保存失败时保留内存内容并提供导出。
- 绘制中的参数变更作用于下一笔；避免一条笔画因 UI 更新改变样式。
- 快捷键初稿：B 画笔、E 橡皮、Cmd/Ctrl+Z 撤销、Shift+Cmd/Ctrl+Z 重做；输入框获得焦点时不拦截文字输入。
- 触控笔优先模式仅在可识别输入条件下启用，不宣传未经真实设备验证的防误触能力。
- 动画用于面板、反馈与切换，尊重 reduced-motion；绘制反馈不增加人为延迟。

## 4. 技术选型

| 部分 | 选择 | 原因 |
| --- | --- | --- |
| 仓库 | pnpm workspace | 网站与包共享源码，起步无需额外任务编排工具 |
| 网站 | React + TypeScript + Vite | 适合客户端交互工具，静态托管即可运行 |
| 样式 | CSS Modules + CSS variables | 统一设计令牌，控制视觉与主题，减少运行时负担 |
| 引擎 | TypeScript + Canvas 2D | 框架无关，输入与渲染可拆分 |
| 数据 | 版本化 JSON 文档 + IndexedDB | 可恢复、可迁移，作品留在本地 |
| 测试 | Vitest + Playwright | 算法/历史单元测试与浏览器完整流程验证 |
| 包构建 | TypeScript ESM + 类型声明 | 输出 ESM 和类型声明，控制发布文件 |
| CI | GitHub Actions | 安装、类型检查、测试、构建与包消费验证 |
| 托管 | 静态部署 | 不引入第一版不需要的后端；发布阶段确定地址与服务 |

实施时查询兼容的稳定版本，记录 Node 要求并提交 lockfile，不使用未经验证的预发布版本。核心包不依赖 React；第一版 ESM 优先，只有明确使用场景才增加 CJS。正式 npm 名称与发布身份在发布前核实；产品名 Calamus 不依赖裸包名是否可用。

官方参考：https://react.dev/versions · https://vite.dev/guide/ · https://www.typescriptlang.org/docs/ · https://vitest.dev/guide/ · https://playwright.dev/docs/intro

## 6. 核心架构约束

1. 文档是事实来源，Canvas 是渲染结果。UI 不直接修改引擎内部状态。
2. 文档包含 schemaVersion、逻辑尺寸、背景、顺序笔画；笔画包含 ID、工具、颜色、宽度、平滑参数、算法版本和采样点。
3. 采样点包含 x/y、相对时间、压力、输入类型；压力不可用与真实零压力必须区分。
4. 每笔开始时冻结配置；文档查询返回不可变视图或安全副本。
5. 输入点由 client 坐标转换为逻辑坐标，独立处理 DPR 与视图变换；重绘不会重写原始坐标。
6. 输入层处理 pointer capture、pointercancel、失去捕获、窗口失焦和组件卸载；取消笔画不留下卡住的绘制状态。
7. 活动笔画与已完成内容分层渲染。初期历史变化可完整重绘，按测量结果引入缓存，避免无限增长的全画布快照。
8. 整笔擦除作为文档命令，一次拖动作为一次历史操作；清空同样可撤销；新操作使 redo 分支失效。
9. 保存、导入、回放共用同一套笔画处理逻辑；算法不能依赖回放机器的实时执行速度。
10. JSON 导入先校验版本、类型、有限坐标、尺寸、点数与容量上限，再原子替换文档；失败不破坏现有作品。
11. 自动保存串行或使用修订号，防止旧写入覆盖新作品；保存状态只有在事务完成后才显示成功。
12. 包导入时不访问 window/document；创建画板时才要求 DOM；destroy 释放事件、观察器和动画任务。

核心 API 草案（设计目标，尚未实现）：

```ts
const board = new Calamus(canvas, options);
board.setBrush({ color: '#263831', size: 4 });
board.setTool('pen');
board.undo();
board.redo();
board.clear();
const data = board.toJSON();
board.load(data);
const png = await board.exportPNG({ scale: 2 });
const unsubscribe = board.on('change', listener);
unsubscribe();
board.destroy();
```

## 实施记录

- 首个原型包含固定尺寸画布、基础触控笔压感、画笔调色和粗细、纸面辅助网格、撤销重做、清空和 PNG 导出。PNG 导出使用纯色纸底。
- 网站通过核心包入口创建 Calamus 实例；输入、渲染与历史由核心引擎处理，网站负责界面、文件操作和本地存储。
- 执行 `pnpm install --frozen-lockfile` 安装依赖，再用 `pnpm dev` 启动。开发期包名为 `@calamus/core`。
- P1–P3 当前桌面验收已完成；下一阶段进入 P4 多作品管理。跨浏览器与真实触控设备检查继续单独跟踪。

## 8. 测试与质量要求

- 单元测试优先覆盖坐标变换、文档校验、历史分支、序列化与确定性笔画处理。
- 浏览器测试覆盖绘制→撤销→恢复→导出、刷新恢复、缩放定位、取消输入和生命周期清理。
- 浏览器目标为当前稳定版 Chromium、Firefox、Safari；自动化 WebKit 不等同于真实 iPad/Safari 验证。
- 视觉检查覆盖宽屏、平板、手机，检查溢出、遮挡、可读性与焦点。
- 画布本身的无障碍限制如实说明，工具栏、弹窗和作品列表提供完整键盘与读屏支持。
- 每阶段运行相关检查；阶段完成后更新本文件并记录验证与限制。

## 9. 执行节奏

按 P1 → P2 → P3 → P4 → P5 → P6 → P7 推进，每阶段交付可验证增量。P1–P3 完成后形成首个可用版本；P4–P5 提升展示质量；P6–P7 完成开源发布。

每次交付说明：本次完成项、运行方式、验证结果、已知限制、下一阶段。普通实现选择按本计划推进；真正缺失的发布身份与真实设备验证条件到需要时再补充。
