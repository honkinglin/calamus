# 回放查找基准

运行 `pnpm bench:replay`。脚本先构建核心，再输出 JSON；任一对照输出不一致会直接失败。

比较逐笔查找与播放会话索引，在单笔 100000 点、10000 笔各 10 点两种数据下，分别查询 1%、50%、99% 时间位置。使用整数时间戳排除两种算法已知的小数边界语义差别；小数正确性由回归测试覆盖。

每组先校验完整输出，再预热 5 轮，交替执行两种实现采样 30 轮，记录中位数与 P95。索引建立耗时单独记录，仅一次样本，不能与重复测量中位数直接比较。

此次报告：`benchmarks/replay-lookup-2026-11-16.json`。多笔画三个位置的中位数由约 0.0057/0.0772/0.0597ms 变为 0.0005/0.0074/0.0058ms；单笔长线约持平，50% 位置索引版本略慢。亚毫秒测量受 JIT、调度与 GC 影响，应重复运行看趋势，不设硬性性能门槛。

范围仅限 Node CPU 时间定位与可见数组分配。没有测量 Canvas 重绘、几何生成、GPU、输入延迟或浏览器内存，不能据此宣称实际回放 FPS 提升。索引增加 O(笔画数) 会话内存；后续需继续浏览器端验收。
